Contoh Kode

Rancangan tabel notes

CREATE TABLE notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  latitude REAL,
  longitude REAL,
  updated_at INTEGER NOT NULL,
  sync_status TEXT NOT NULL DEFAULT 'PENDING'
);
Baca tabel ini seperti membaca formulir. Id adalah nomor unik, title dan content wajib terisi, latitude dan longitude boleh kosong karena tidak semua catatan punya lokasi. Kolom sync_status adalah siasat untuk nanti: ia menandai catatan yang belum dikirim ke server.

Buka simulasi SQLite atau MySQL dan pilih tiap kebutuhan. Minta peserta menebak jawabannya dulu. Intinya: SQLite untuk penyimpanan lokal di ponsel, MySQL untuk data bersama di server, dan keduanya dihubungkan lewat API.

Konsep

Mengapa ponsel tidak langsung ke MySQL

  • Kata sandi basis data harus ada di aplikasi, dan aplikasi dapat dibongkar.
  • Port MySQL terbuka ke internet, menambah risiko serangan.
  • Tidak ada tempat memeriksa hak akses dan validasi per pengguna.
  • Solusi: ponsel memanggil **API** (HTTPS + token), API yang berbicara ke MySQL. Skema contoh ada di shared/server/schema.sql.
Ini pertanyaan yang hampir pasti muncul. Jelaskan tiga alasan: kata sandi basis data ikut di aplikasi dan aplikasi bisa dibongkar, port basis data terbuka ke internet, dan tidak ada tempat memeriksa hak akses. Jembatannya adalah API, yang kita bangun di hari kedua.

Repository dan CRUD

Tiga fungsi: baca semua, simpan (tambah atau ubah), hapus. Parameter memakai tanda tanya.

src/data/noteRepository.ts

export async function simpanCatatan(n: Note): Promise<void> {
  const db = await getDb();
  if (n.id == null) {
    await db.runAsync(
      'INSERT INTO notes (title, content, latitude, longitude, updated_at, sync_status) VALUES (?, ?, ?, ?, ?, ?)',
      [n.title, n.content, n.latitude, n.longitude, n.updatedAt, n.syncStatus],
    );
  } else {
    await db.runAsync(
      "UPDATE notes SET title = ?, content = ?, latitude = ?, longitude = ?, updated_at = ?, sync_status = 'PENDING' WHERE id = ?",
      [n.title, n.content, n.latitude, n.longitude, Date.now(), n.id],
    );
  }
// ... selengkapnya di berkas ini
Repository adalah satu-satunya tempat yang boleh menulis SQL. Halaman hanya memanggil fungsi seperti simpanCatatan. Perhatikan tanda tanya pada perintah SQL: nilai dikirim terpisah dari perintah, sehingga pengguna tidak bisa menyisipkan SQL berbahaya lewat isian. Buka simulasi CRUD dan lakukan tambah, ubah, hapus.

Konsep · simulasi: tekan S

Model berlapis dan sinkronisasi

  • **Lapisan**: tampilan (halaman) memanggil repository, repository memanggil SQLite.
  • **Offline-first**: simpan ke SQLite dahulu, kirim ke server saat ada koneksi.
  • Kolom sync_status menandai data **PENDING** (belum dikirim) atau **SYNCED**.
  • Konflik sinkronisasi biasanya diselesaikan dengan updated_at terbaru.
Gambarkan tiga lapis di papan: tampilan, repository, penyimpanan. Tiap lapis hanya berbicara dengan lapis di bawahnya. Lalu jelaskan offline-first: simpan lokal dulu agar aplikasi cepat dan tetap jalan tanpa sinyal, kirim ke server saat ada koneksi. Buka simulasi offline untuk melihat status PENDING berubah menjadi SYNCED.

Pelacak Kebiasaan dengan SQLite

Buat pelacak kebiasaan harian (minum air, olahraga, membaca). Pengguna menambah kebiasaan dan mencentang kebiasaan yang selesai hari ini. Data harus tetap ada setelah aplikasi ditutup.

  • Dua tabel: habits (id, nama, dibuat) dan logs (id, habit_id, tanggal) dengan kunci asing.
  • Lapisan repository terpisah dari tampilan: tambah, baca, ubah, hapus kebiasaan, serta catat dan batalkan centang.
  • Satu migrasi: tambahkan kolom warna pada habits tanpa menghapus data lama.
  • Layar daftar dengan jumlah hari berturut-turut (streak) per kebiasaan.
  • Jawaban tertulis tiga kalimat: mengapa aplikasi ini memakai SQLite dan bukan MySQL langsung?
