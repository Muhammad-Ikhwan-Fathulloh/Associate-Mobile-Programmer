Konsep

Apa itu API

  • **API** adalah pintu bagi program lain untuk meminta atau mengubah data.
  • **REST** memakai alamat (URL) untuk sumber daya dan **metode HTTP** untuk aksinya, data umumnya **JSON**.
  • Aplikasi adalah **klien**, server menjawab. Satu permintaan, satu jawaban.
Pakai analogi pelayan restoran: aplikasi adalah tamu, API adalah pelayan, dapur adalah server dan basis data. Tamu tidak masuk ke dapur. Dari sini mudah menjelaskan mengapa ponsel tidak langsung ke basis data.

Konsep

Server latihan

  • Ada di shared/server: Express, penyimpanan di memori, npm start pada port 3000.
  • Login contoh: peserta@contoh.id dengan kata sandi rahasia123. Server mengembalikan **token**.
  • Emulator Android mengakses komputer lewat 10.0.2.2. Ponsel fisik memakai alamat IP komputer di Wi-Fi yang sama.
  • Tersedia 4 pengujian otomatis: npm test.
Pandu peserta menjalankan server dan membuka alamat health di peramban. Bila ada yang gagal, periksa dulu apakah port 3000 dipakai dan apakah emulator memakai 10.0.2.2. Ponsel fisik wajib satu Wi-Fi dengan komputer.

Konsep · simulasi: tekan S

Menangani kegagalan

  • Status 4xx: tampilkan pesan dari server (error).
  • Timeout atau jaringan mati: simpan sebagai PENDING, coba lagi nanti.
  • Jangan membaca body kosong (204) sebagai JSON.
  • Aplikasi tidak boleh macet: selalu ada batas waktu.
Buka simulasi jaringan atau ubah kondisi pada simulasi REST. Buat peserta menyebut tindakan untuk tiap kegagalan: tampilkan pesan, biarkan PENDING, atau arahkan login. Aplikasi yang baik tidak pernah macet menunggu.

Proyek Modul 5 · 60 menit

Klien API Catatan

Hubungkan aplikasi ke server latihan (shared/server). Pengguna login, melihat daftar catatan dari server, dan membuat catatan baru. Kesalahan server ditampilkan dengan pesan yang ramah.

  • Server latihan berjalan (npm start) dan dapat dijangkau dari emulator (10.0.2.2) atau ponsel (IP komputer).
  • Klien API terpisah dari tampilan: login, daftarCatatan, buatCatatan.
  • Header Authorization: Bearer <token> dikirim pada rute catatan.
  • Pesan error dari server (error) ditampilkan, bukan teks teknis.
  • Batas waktu permintaan (timeout) dan penanganan server mati.
  • Minimal 4 tes klien dengan fetch atau http.Client palsu.

Brief lengkap: shared/docs/proyek/modul-5-klien-api-catatan.md

Proyek ini adalah irisan kecil yang bisa berdiri sendiri dan nanti dapat digabung ke proyek akhir. Bacakan skenario, lalu minta peserta memilih satu syarat yang paling menantang bagi mereka. Kriteria penerimaan dan rubrik ada di brief lengkap.
