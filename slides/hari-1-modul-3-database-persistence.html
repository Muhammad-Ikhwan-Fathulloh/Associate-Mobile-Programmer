Perancangan

Perancangan Tabel

  1. Identifikasi entitas, misalnya notes.
  2. Tentukan atribut dan tipenya.
  3. Tentukan primary key dan kolom wajib.
  4. Tentukan relasi melalui foreign key.
  5. Tambahkan indeks pada kolom yang sering dikueri.
notes
├── id          INTEGER  PRIMARY KEY AUTOINCREMENT
├── title       TEXT     NOT NULL
├── content     TEXT     NOT NULL
├── latitude    REAL
├── longitude   REAL
├── updated_at  INTEGER  NOT NULL
└── sync_status TEXT     NOT NULL DEFAULT 'PENDING'

Database

Database Helper

static Future<Database> get instance async {
  final existing = _database;
  if (existing != null) return existing;

  final path = join(await getDatabasesPath(), 'associate_mobile.db');
  final db = await openDatabase(
    path,
    version: 1,
    onConfigure: (db) async {
      await db.execute('PRAGMA foreign_keys = ON');
    },
    onCreate: _buatTabel,
  );
  _database = db;
  return db;
}
  • Koneksi disimpan agar database tidak dibuka berulang.
  • onCreate hanya dipanggil saat database pertama kali dibuat.

CRUD

Repository (CRUD)

Future<List<Note>> ambilSemua() async {
  final db = await AppDatabase.instance;
  final rows = await db.query('notes', orderBy: 'updated_at DESC');
  return rows.map(Note.fromMap).toList();
}

Future<int> simpan(Note note) async {
  final db = await AppDatabase.instance;
  final values = note.toMap()..remove('id');
  return db.insert('notes', values);
}

Future<int> hapus(int id) async {
  final db = await AppDatabase.instance;
  return db.delete('notes', where: 'id = ?', whereArgs: [id]);
}
  • whereArgs mencegah SQL injection. Jangan menggabungkan input pengguna ke string SQL.

State

State dengan ChangeNotifier

class NoteController extends ChangeNotifier {
  List<Note> _notes = const [];
  bool _isLoading = false;

  Future<void> load() async {
    _isLoading = true;
    notifyListeners();
    try {
      _notes = await _repository.ambilSemua();
    } finally {
      _isLoading = false;
      notifyListeners();
    }
  }
}

Konsep

Offline-First dan Sinkronisasi

  • Data ditulis ke database lokal terlebih dahulu, lalu disinkronkan ke server di latar belakang.
  • Kolom sync_status menandai data: PENDING, SYNCED, atau FAILED.
  • Antrean unggahan dijalankan saat koneksi tersedia.
  • Resolusi konflik, misalnya last-write-wins berdasarkan updated_at.
